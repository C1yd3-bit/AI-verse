## Implemented behavior

- Upload uses measured native XHR progress, accessible progress/status, cancellation and a deadline bounded by grant expiry and fifteen minutes. Unknown transfer length stays indeterminate. Transfer completion never claims that processing, review or publication has completed.
- A recovery journal binds the confirmed account and immutable version before the grant request. It stores identifiers, never bearer URLs, tokens, file data or credentials. Cancellation, ambiguous grant/upload outcomes, account loss, unmount and reload do not authorize a blind second grant. Check status and follow the operator recovery path.
- Browser grants require the exact expected owner/version, bounded response, future finite expiry and canonical HTTPS upload host. Binary transfer omits credentials and uses a no-referrer policy. Studio initial reads, refreshes, writes and thumbnail actions share account/generation and operation boundaries; uncertain writes preserve inputs and block new writes until explicit recovery.
- Optional still JPEG/PNG/WebP thumbnails are limited to5MiB/16MP and normalized with metadata stripped to a proportion-preserving WebP, maximum1280px/256KiB. SVG, animation, MIME mismatch, invalid/oversized payloads and decode/read timeouts are rejected. Cheap authorization precedes image processing; the final sealed service RPC repeats ownership/latest-draft/no-reservation checks under locks.
- Only the verified approved creator can edit their latest unreserved private draft thumbnail. Reservation/review freezes it. Moderators receive the exact revision's private thumbnail; a present image must decode before a decision can proceed. Failure offers a real reload. An explicitly absent thumbnail is a valid review state.
- Anonymous artwork reads admit only the active published version of an eligible creator, with `no-store`. They never fall back to a signed-in private read. Public catalog adds only `has_artwork`; safe application-owned artwork paths replace empty live thumbnails. Catalog, Reels, detail and assistant image consumers bypass the Next image optimizer for live artwork so each request rechecks publication eligibility. Personalized recommendations preserve approved thumbnails.
